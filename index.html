B1監控頁：新增需求（AI 自動查詢）

不知道要看哪個網站時，用這個方式。AI 會上網找官方售票網站和開賣規則，再讓你勾選要監控哪些。

  1. 想訂的項目：寫清楚一點（範例：日本環球影城門票）
  2. 目標日期：要入場／使用的日期（範例：2027/02/25）
  3. 備註：人數、票種、想買官方或代理商…AI 查詢時會參考
  4. 每天檢查時間：選每天 1／2／3 次，時間可以改（台灣時間）。建議保留早上一次
  5. 預計開放時間：不知道就留空，AI 查到會自動填
  6. 網址來源：選「🤖 AI 自動查詢」
  7. 按 新增需求，約 1～2 分鐘後下方會列出 AI 找到的網站，勾選後按加入

B2監控頁：新增需求（自己填網址）

已經知道官方網站、或官方有固定開賣規則時用這個。範例：大阪海遊館的 eチケット「來館日 30 天前開賣」。

  1. 預計開放時間：官方公告的開賣時間（範例：2026/12/04 00:00）
  2. 時區：選開賣地的時區（範例：東京）。系統會自動換算成台灣時間
  3. 網址來源：選「自己填網址」
  4. 網址：一行一個，貼官方網站（範例：https://www.kaiyukan.com/info/ticket/）
  5. 按 新增需求。到預計開放時間後約 10 分鐘會再檢查一次並通知，前一天也會先提醒

⚠️ Klook、KKday、Trip.com 這類網站會擋程式，貼了會一直「讀取失敗」，網頁也會跳出提醒。請改貼官方網站，或用 AI 自動查詢。

B3監控頁：看狀態

  1. 項目名稱（橘紅色）與目標日期、每天檢查時間
  2. ＋網站：多加一個監控網站；編輯：改日期、檢查時間、預計開放時間；暫停／刪除
  3. 預計開放：台灣時間（括號內是當地時間）＋倒數天數，下面一行是官方開賣規則
  4. 網站：監控的網址
  5. 狀態：監控中 已開放！ 讀取失敗 已暫停
  6. 上次確認／結果／下次確認：程式什麼時候看過、看到什麼、下次什麼時候看
  7. 立即檢查：馬上請 GitHub 檢查一次（約 1 分鐘出結果）

B4監控頁：調整偵測條件（進階）

點網站那一列可以展開。一般不用改，AI 或範本會自動設好。

  1. 完整結果：上次檢查的完整說明
  2. 偵測條件：怎麼判斷「開賣了」，可以加多個
    • 到達預計開放時間：時間到就通知（官方有固定規則、但網站擋程式時用，例如海遊館、USJ）
    • 文字出現／文字消失：例如出現「2027」、「準備中」消失
    • 元素出現／按鈕可點：網頁上出現某個購買連結或按鈕
    • 出現目標日期、頁面有變動、AI 判斷
  3. 條件判斷：「任一成立就通知」或「全部成立才通知」
  4. 改完按 儲存條件；重設狀態會讓「已開放」的項目重新開始監控

C準時觸發器（強烈建議設定）

GitHub 內建的定時排程在尖峰時段常常延遲好幾小時，甚至直接略過（實測一天只跑了幾次），會讓「09:30 檢查」拖到下午才做。 設定一個免費的 Google Apps Script，它每 10 分鐘看一次：有網站到了檢查時間才請 GitHub 執行，檢查最多晚 10 分鐘，也不浪費 GitHub 的免費分鐘數。

  1. 建一組專用 Token：GitHub → Fine-grained token
    • Repository access：只選 booking-reminder
    • Permissions：Actions → Read and write、Contents → Read-only（其他都不用）
  2. 建立腳本：打開 script.google.com 新專案， 把 這個檔案 的內容全部複製貼上，按 💾 儲存
  3. 填設定：左側 ⚙️「專案設定」→ 最下面「指令碼屬性」→ 新增三個：
    • GITHUB_TOKEN：第 1 步的 Token
    • REPO：Austine-ho/booking-reminder
    • SUMMARY_TIME：23:00（和每日總覽時間一樣）
  4. 啟動：回到編輯器，上方函式選 setup → 按「執行」→ 依指示授權
  5. 確認：函式改選 tick → 執行，下方記錄出現「已觸發」或「沒有到時間的項目」就完成了

?常見問題

一直顯示「讀取失敗 403」？
那個網站擋程式（Klook、KKday 最常見）。請改成官方網站，或刪掉後用「🤖 AI 自動查詢」重新新增。
通知會比實際開賣晚嗎？
會晚一點：GitHub 每 30 分鐘喚醒一次，尖峰時段可能再晚 10～30 分鐘。這個工具是「通知你今天開賣了」，不是搶票用。
AI 結果寫「信心 low」？
AI 看不出來時不會通知你（避免誤報）。這種網站建議偶爾自己打開看看，或改用「到達預計開放時間」條件。
新增需求後沒有反應？
GitHub 版要等 Actions 跑完（約 1 分鐘），頁面每 30 秒自動更新。確認右上角有「GitHub」綠色標籤；沒有的話按「登出」重新登入。
AI 查詢顯示「Groq 今天的免費額度已用完」？
Groq 免費版每個模型每天有 token 上限，AI 查詢會讀很多網頁，查兩三次就可能用完。訊息會告訴你約幾分鐘後恢復。可以在設定填「Groq API Key（備用）」（另一個帳號），用完會自動換；兩組都用完才會用 Gemini（有填的話）。每次的定時檢查用另一個較小的模型，額度分開算。
換手機了？
新手機打開網站，用同一個 GitHub Token 登入即可；資料都存在 GitHub，不會不見。
